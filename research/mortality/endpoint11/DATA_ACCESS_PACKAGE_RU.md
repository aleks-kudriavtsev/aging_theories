# Данные для отдельных причин смерти: технический пакет запроса

**10.09.2026. Проект заявки, не поданная заявка и не предоставленный доступ.**

## Научный вопрос
Оценить, какую дополнительную прогностическую информацию дают рутинные клинико-лабораторные показатели для смерти от ИБС, цереброваскулярных болезней, конкретных опухолей и почечных заболеваний. Разработка и проверка разделяются по участникам и времени; прогноз общей смертности и отдельных причин должен быть согласован.

Для всех заявок отдельно проверяются допустимость участия конкретной организации, стоимость, среда анализа, ограничения вывоза данных и правила публикации агрегатов. Наличие публичного описания не считается выданным разрешением. Не запрашивать персональные идентификаторы, адреса или контакты участников.

## Минимальный запрос переменных

**Связь записей.** Только псевдонимизированный идентификатор внутри разрешённого проекта; идентификатор когорты/центра; дата либо допустимое представление времени исходного обследования; источник и версия linkage.

**Исходы.** Статус жив/умер; длительность наблюдения после забора материала; дата/время цензурирования; первоначальная причина смерти и схема кодирования. Сопутствующие причины — отдельные поля для вторичного анализа, не взаимоисключающие конкурирующие исходы. Неизвестная причина не становится цензурированием. Для CDC запросить доступные в актуальном словаре UCOD_113, детализированную ICD-причину и соответствующие recodes. Названия ICD_10REV/UCOD_358 документированы для2019; их наличие/формат2022 подтвердить до запуска.

**Признаки.** Возраст, зарегистрированный пол, курение, BMI/талия, измерения систолического давления, антигипертензивное лечение, исходные заболевания. Лабораторное ядро: общий холестерин, HDL, HbA1c, креатинин, альбумин/креатинин мочи, альбумин крови, RDW-CV и лейкоциты. CRP и белки расширения запрашивать отдельно при фактическом наличии. Для каждого измерения необходимы единицы, биоматериал, платформа, калибровка, пределы измерения, правила below-LOD и идентификатор партии/периода при доступности. Ни один отсутствующий во всей когорте анализ не объявляется измеренным после заполнения медианой.

**Дизайн.** Веса обследования, strata/PSU или описание выборки; причина недоступности материала/исхода; критерии исключения, даты согласий/этического разрешения на вторичный анализ. Для регистра/биобанка репрезентативность страны не предполагается автоматически.

## Однозначные целевые определения

| Исход | Первоначальная причина | Недопустимая замена |
|---|---|---|
| ИБС | I20–I25 | Все болезни сердца001 |
| Цереброваскулярная смерть | I60–I69 | Только I63 или широкие ССЗ |
| Рак трахеи, бронхов и лёгкого | C33–C34 | Все злокачественные опухоли002 |
| Колоректальная/анальная опухолевая смерть в текущем определении | C18–C21 | Все ЗНО; при исключении C21 менять определение и версию |
| Смерть с ХБП как первоначальной причиной | N18 | Группа009, включающая N17 и другие диагнозы |
| Альцгеймер | G30 | Все деменции F01–F03/G30 |

В словаре2019 ИБС восстанавливается по листовым UCOD_113=059,060,062,063; 058 и061 — подытоги, которые не являются значениями индивидуальных записей. Рак C33–C34 соответствует027, C18–C21 —023, цереброваскулярная смерть —070, G30 —052. **Для N18 даже UCOD_113=100 недостаточно:** эта строка объединяет N17–N19; нужен исходный ICD-код либо другой доказанно достаточный recode [5].

Остальные смерти сохраняются в непересекающемся остатке. Для итогового «естественная неинфекционная смерть» нужен отдельный версионируемый разбор всех кодов, включая инфекционные состояния вне A/B и внешние причины; остаток нельзя объявлять целевым по умолчанию.

## Организация анализа

До просмотра новой проверочной выборки фиксируются полный протокол, список признаков, определения исходов, горизонт, разделение обучения/настройки/проверки, обработка пропусков и метрики. Для редких исходов сравниваются регуляризация и разделяемые между причинами эффекты; число параметров обосновывается моделированием, а не одним универсальным правилом events-per-variable.

Для NCHS RDC запрещено совместно использовать public и restricted mortality linkages в одном проектном анализе [4,10]. Это не запрещает разрешённое соединение публичных исходных обследований с approved restricted linkage. Работа с разрешёнными данными выполняется в предусмотренной держателем среде. В GitHub публикуются только код, спецификации и прошедшие disclosure review агрегаты.
