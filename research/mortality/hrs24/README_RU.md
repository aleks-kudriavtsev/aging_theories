# HRS24: переход к разрешённому анализу совместной панели

15.09.2026. Продолжение joint23; это этап доступа и проверки совместности измерений, не новый анализ NfL и не обучение на HRS.

## Что изменяет маршрут

По действующим документам HRS, человеко-уровневые записи (в том числе псевдонимизированные, производные маски наличия измерений, RAND HRS/Gateway) нельзя передавать в LLM. Разрешены публичная документация, подготовка кода без микро-данных и результаты анализа без микро-данных. Поэтому исполняемый код передаётся допущенному исследователю, работающему в разрешённой среде; сюда возвращаются только прошедшие проверку агрегаты. Изолированная локальная LLM сама по себе не разрешена. Источник: [AI policy](https://hrsdata.isr.umich.edu/data-products/ai-llm-use-policy).

[Sensitive Data Access Agreement](https://hrs.isr.umich.edu/sites/default/files/HRS-Sensitive-Data-Access-Use-Agreement.pdf), редакция 21.08.2026, требует индивидуального соглашения, подписи уполномоченного представителя учреждения и явного перечня продуктов. Дополнительные продукты требуют отдельного согласования. Использование коммерческими аффилированными лицами ограничено исследованием; требуется Attachment A, а консультационные/лицензионные обязательства могут исключать допустимость. Наличие государственного задания не заменяет рассмотрение HRS. Заявка не подписана и не отправлена.

[HRS FAQ](https://hrs.isr.umich.edu/data-products/restricted-data/faqs) запрещает доступ к NDI/CMS-связанным данным из-за пределов США. Это касается и доступа к американской машине из другой страны. Поэтому для первого запроса необходимо подтвердить допустимый источник жизненного статуса/сроков наблюдения; точные ICD-причины не предполагаются автоматически.

## Новая конкретика по переменным

Официальный [Supplemental codebook](https://hrs.isr.umich.edu/sites/default/files/meta/vbs/supplemental/codebook/vbs16aaa_r.htm) содержит:

| Переменная | Измеряемый объект | Роль |
|---|---|---|
| PIL6 | IL-6 | Выпущенная переменная подтверждена; единицы, метод и контроль качества требуют сверки перед импортом |
| PTNFR1 | Растворимый TNFR1 | Отдельный аналит; не заменяет прямой TNF-alpha |

Обе опубликованные маргинальные ненулевые по наличию выборки имеют n=9831; это не размер совместной панели. Прямой TNF-alpha не перечислен в проверенном Supplemental-файле, но отсутствие во всех HRS-продуктах не доказано. GDF15 описан в дополнительном нейробиомаркерном выпуске; точные выпущенные имена остальных белков не угаданы. `VERIFIED_MAPPING.json` сохраняет эти уровни подтверждения. Страница продукта и codebook используют разные метки версии (v1.0 и VERSION=2, April2025); это вынесено в вопрос держателю.

## Реализация

`access.py` проверяет сведения о доступе до открытия таблицы участников. HRS-microdata в режиме AI, GitHub Actions, публичного веб-приложения или неизвестной среды блокируются, даже когда оператор указал наличие соглашения. Это проверка заявленных условий, не техническая аттестация среды или удостоверение юридической силы соглашения.

`feasibility.py` принимает подготовленную держателем таблицу **наличия пригодных измерений**, а не концентрации. Такая таблица с HHID/PN всё ещё является microdata. Её нельзя загружать в чат. Нужны ровно столбцы `HHID,PN,baseline_token,component,usable`. `HHID` и `PN` сохраняются строками ширины 6 и 3; значения `usable` — 0/1 после согласованного контроля качества. Положительная отметка не создаётся из одного факта наличия числового значения ниже LOD.

Исследователь обязан сам подтвердить сопоставление baseline-token с действительным исходным визитом/образцом, единицы, методы и версии файлов. Программа не угадывает это по году. Смена визита, дубликаты человек-компонент, неподтверждённая молекулярная форма и подмена TNF рецептором блокируются. Итог — только агрегированные размеры общей клинической панели, полного core13, явно указанного общего core и белковых расширений на одном визите. Исходы смертности на этом этапе не читаются.

Файл результата помечается INTERNAL ONLY и **не разрешён для автоматической передачи**. Группы перекрываются, поэтому даже большие счётчики могут раскрывать малые разности. `review_partition` — лишь консервативная помощь для одной непересекающейся таблицы: при любой ячейке меньше пяти скрывается вся таблица и итог. Он не обеспечивает защиту от объединения нескольких опубликованных таблиц. Действует человеческая проверка раскрытия.

## Необходимое научное решение до исходов

Если UACR, HbA1c или другие элементы исходной панели отсутствуют на совместном визите, утверждается отдельный HRS-compatible core и новая процедура разработки/проверки. Отсутствующие показатели не становятся «нормальными»; коэффициенты старой модели не применяются к незаявленному сокращению. Сравнение всегда на одинаковых участниках. Проект последовательности: core против core+GDF15/IL6/GFAP; затем добавления NT-proBNP/CST3/NfL; прямой TNF — только при реальном измерении. Это проект до фиксации доступных переменных, не объявленная выполненная проверка.

## Запуск

В этой поставке только проверки на полностью искусственных данных:

```bash
python -S -m unittest discover -s tests -p test_hrs24.py -v
```

Следующая команда предназначена **только для человека с одобренным HRS-доступом, вне AI-среды**:

```bash
python -S -m research.mortality.hrs24.feasibility \
  --config operator_config.json --presence local_presence.csv \
  --out LOCAL_ONLY_feasibility.json
```

Пустой `operator_config.template.json` блокирует чтение данных. Не заполняйте флаги согласования без действительного разрешения. Программа не содержит загрузчика, логина, сетевых запросов, обучения или публикации. Старые модели, приложение и их коэффициенты не изменены; новый модуль запускается из исходников и не добавлен в прежний wheel.

## Поставка

Политика доступа, перечень источников, проверенные сопоставления, код и синтетические тесты могут быть публичными. Заявка с личными/институциональными реквизитами, подписи, защищённые файлы и индивидуальные результаты не публикуются. Индивидуальные HRS-данные в этой итерации не получены. Англоязычный запрос подготовлен отдельно для согласования, а не автоматически отправлен.
