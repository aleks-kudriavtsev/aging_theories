# Обмен с системой отбора биомаркеров

`research.mortality.export_system_evidence` передаёт в `aging_biomarkers` пять
конфигураций Mortality Studio и 51 контекстную оценку из двух опубликованных
агрегированных файлов. Получатель связывает измерения с литературными кандидатами
и запускает исходную замороженную модель через отдельный адаптер.

Экспорт предназначен для git checkout с исходными документами, а не установленного
runtime wheel. Он использует только стандартную библиотеку Python и сверяет
научные входы с коммитом `1e5772ad813ef0d3f1a18f36c4bf34949972e039`.

```bash
python -S -m research.mortality.export_system_evidence \
  --source-commit 1e5772ad813ef0d3f1a18f36c4bf34949972e039 \
  --out /tmp/aging_theories_evidence.json
python -S -m unittest discover -s tests -p test_system_evidence_export.py -v
```

Контракт `aging_system_evidence/1.0` сохраняет модель, исход, число состояний,
горизонт, когорту, популяцию, страну, пол, возраст, метод учёта цензурирования и
условный характер интервала. Каждый численный результат содержит SHA-256
исходного документа и точный JSON pointer. Отрицательные оценки и интервалы,
пересекающие ноль, сохраняются. Байты двух исходных JSON включены для проверки.
Коэффициенты и индивидуальные данные участников не экспортируются.

Клинический контроль не использует лабораторные предикторы, хотя интерфейс требует
общий полный профиль сравнения. Входной креатинин и производная eGFR, UACR и его
исходные измерения, RDW-CV и RDW-SD не отождествляются. Оценка совместного блока не
приписывается отдельному маркеру. `full8` и `full8_detailed` — разные представления
одного набора коэффициентов, а не независимые обученные модели.

Принимающая сторона находится в `aging_biomarkers`, модули
`tools.mortality_graph.model_evidence` и `tools.mortality_graph.model_bridge`.
Полный порядок запуска: `docs/MODEL_SYSTEM_INTEGRATION_RU.md` того репозитория.
Литературные эффекты и баллы теорий не подставляются в коэффициенты NHANES.
Исторические оценки качества не становятся результатом проверки интеграции;
прогоны синтетических профилей проверяют только расчётный путь.

Статус `external18` передаётся как подготовленный протокол без выполненной
валидации на реальных RU/DE когортах. Изменений модели, клинических разрешений
или новых статистических результатов этот экспорт не создаёт.
