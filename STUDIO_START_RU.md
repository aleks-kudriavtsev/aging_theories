# Mortality Studio 0.16

Единое локальное исследовательское приложение: измерения → проверка входа → выбранная замороженная модель → вероятность выживания/причин смерти → HTML/JSON с происхождением и областью проверки.

## Запуск из исходников

Python 3.10 или новее. Сторонние библиотеки для расчёта и интерфейса не нужны.

```bash
python3 -m research.mortality.studio16 doctor
python3 -m research.mortality.workbench studio
# То же напрямую:
python3 -m research.mortality.studio16 serve
```

Открыть `http://127.0.0.1:8766`. Явно выбрать модель и нажать «Синтетический пример», затем «Проверить и рассчитать». Это вымышленные входы для проверки программы, не пациент и не клинический результат.

## Установка wheel

```bash
python3 -m pip install --no-deps mortality_workbench-0.16.0-py3-none-any.whl
mortality-studio doctor
mortality-studio serve
# Команда прежнего приложения сохранена:
mortality-workbench studio
```

На Windows используется `python` вместо `python3`. Старые `mortality-workbench serve/predict` воспроизводят прежний интерфейс и расчёт 0.7; новый единый интерфейс открывает команда `studio`. Не переносите исполняемые файлы между средами: установите wheel в нужный Python.

## Режимы

| Режим | Входы | Выходы и горизонты |
|---|---|---|
| compact4 | Клинические сведения, HbA1c, креатинин, UACR, альбумин | 3 широкие причины + выживание, 1/3 года |
| six6 | Компактный профиль + общий холестерин и HDL | 3 широкие причины + выживание, 1/3 года |
| full8 | Шесть показателей + RDW-CV и лейкоциты | 3 широкие причины + выживание, 1/3 года |
| clinical3 | Общий полный профиль для сравнения; анализы не используются как предикторы | 3 широкие причины + выживание, 1/3 года |
| full8_detailed | Полный профиль | 5 широких причин + выживание, 1/4/5 лет |

Панели с четырьмя и шестью лабораторными результатами требуют не менее пяти и семи определений аналитов: UACR — отношение двух измерений мочи. Это не измеренная стоимость и не число лабораторных процедур.

Кнопка сравнения доступна для полного профиля в трёхпричинном режиме. Четыре прогноза показаны раздельно; их нельзя усреднять, складывать или выбирать по желаемому проценту. Исходные исследования сравнивали панели на общем полном профиле; сокращённые требования ввода не означают отдельной валидации на всех пациентах с пропусками.

## Работа с файлами

```bash
python3 -m research.mortality.studio16 example --model full8 > input.json
python3 -m research.mortality.studio16 predict input.json --out reports/new_profile
python3 -m research.mortality.studio16 compare input.json --models clinical3 compact4 six6 full8 --out reports/comparison
python3 -m research.mortality.studio16 batch inputs.jsonl --out batch_results.json
```

Каталоги отчётов и файлы пакета не перезаписываются. В пакетном JSONL повреждённая запись сохраняется как заблокированная строка; она не исчезает и не превращается в нулевой риск.

## Ограничения

Только исторические модели США, возраст при обследовании 40–79 лет, заявленные горизонты. Инфекции, внешние причины и неизвестные причины сохраняются в остаточной категории. Нельзя трактовать результат как чистую естественную неинфекционную смертность, риск конкретной ИБС/локализации рака, диагноз, биологический возраст, эффект вмешательства или современные национальные риски России/Германии.

Значения вне обучающего диапазона ограничиваются точно по замороженному преобразованию; все такие признаки явно отмечаются в отчёте. Пределы ввода — технические границы, не референсные интервалы. Методы, материалы и единицы не заменяются по сходству названий; например, плазменный альбумин не выдаётся за сывороточный.

Сервер слушает только127.0.0.1, не делает внешних запросов и не пишет введённые данные в файлы/журнал. Это development-сервер, не промышленный медицинский сервис. Сохранённый пользователем отчёт содержит измерения: не публикуйте его в открытом GitHub. Для совместной работы используйте псевдонимизированные исследовательские данные в разрешённой инфраструктуре; приложение не является системой правового или этического допуска.

Новые коэффициенты и клинические метрики этой сборкой не создаются. Три исходных файла моделей сохраняют прежние SHA-256.
